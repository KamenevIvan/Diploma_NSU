# Каркас пайплайна: тестирование устойчивости диалоговых агентов к манипуляции

Первая версия: четыре независимые агентные обёртки + слой доступа к моделям.
Многоходовой оркестратор и логирование уже есть (`run_episode.py`), датасеты пока игрушечные.

## Многоходовые прогоны

```bash
poetry run python run_episode.py --mock                      # без сети, на заглушках
poetry run python run_episode.py --goal all --episodes 3 --max-turns 5
poetry run pytest                                            # тесты (на заглушках)
```
Модели по ролям - в `config.py`, политика и цели атаки - в `scenarios.py`. Результаты: `runs/<время>/trace.jsonl`
(структурированные события) и `transcript.log` (читаемый журнал). Бесплатные API ограничены по запросам и токенам:
расход копится в `backend.usage` и пишется в `episode_end`.

## Структура

```
run_demo.py              # демо: каждый агент вызывается отдельно (smoke-тест связи с моделью)
run_episode.py           # многоходовые прогоны + логи + сводка (ASR по целям)
config.py                # модели по ролям (реальные и заглушки)
scenarios.py             # политика бота и цели атаки
tests/                   # pytest
manip_tester/
  schemas.py             # Tactic, AttackGoal, Turn, PlannerDecision, Verdict
  llm.py                 # бэкенды моделей: OpenAICompatibleBackend, MockBackend, make_backend
  tactics.py             # 7 базовых тактик (Чалдини) + загрузчик PAP-таксономии (40 техник)
  agents.py              # PlannerAgent, AttackerAgent, TargetAgent, EvaluatorAgent
  orchestrator.py        # run_episode: один многоходовой эпизод
  trace.py               # TraceLogger: JSONL + читаемый транскрипт
```

Запуск: `python run_demo.py` (нужен только Python 3.10+; для реальных моделей `pip install openai`).

## Как подключить нейросеть

Все агенты ходят в модель только через `llm.chat(messages, ...) -> str`.
Модель выбирается конфигом для каждой роли отдельно (`ROLE_SPECS` в `run_demo.py`):

| Куда подключаем | Спецификация |
|---|---|
| Локально через Ollama (RTX 2080 Super) | `{"provider": "openai_compatible", "model": "qwen3:8b", "base_url": "http://localhost:11434/v1"}` |
| Облачный API | `{"provider": "openai_compatible", "model": "<имя модели>", "api_key_env": "OPENAI_API_KEY"}` (при другом `base_url` - любой совместимый провайдер) |
| Сервер университета (V100) | поднять на нём vLLM/Ollama и указать его `base_url` (при закрытом порте - через SSH-туннель) |
| Что-то совсем своё | написать класс с методом `chat(messages, *, temperature, max_tokens, json_mode) -> str` и добавить ветку в `make_backend` |

Тег модели в Ollama проверяйте через `ollama list`. Если у конкретной модели другие
имена параметров запроса - это правится в одном месте: `OpenAICompatibleBackend.chat`.

## Практические подводные камни

- **Блоки `<think>`**: модели с режимом рассуждений (Qwen3 и др.) выдают их в ответе. Они вырезаются в `strip_thinking`. Если ответ после этого пустой - вероятно, `max_tokens` слишком мал.
- **JSON-режим**: не все серверы поддерживают `response_format`. Выключается флагом `use_json_mode: False`; парсер `extract_json` и ретрай работают и без него.
- **Отказы атакующего**: модели с сильным safety-тюнингом могут отказываться играть "манипулирующего клиента". Сценарии намеренно безобидные (обойти политику возврата), но если отказы будут - пробуйте открытую модель или переформулируйте системный промпт.
- **8 ГБ VRAM**: одновременно держать в памяти несколько разных локальных моделей не выйдет (Ollama будет подгружать/выгружать - медленно). Практично: атакующий и цель - одна локальная модель с разными системными промптами, "умные" планировщик и оценщик - через API или на сервере.
- **Оценщик**: другое семейство моделей, чем у цели (self-preference bias), `temperature=0`, обязательная проверка на размеченном людьми наборе.
- **Цель без инструментов**: пока бот только пишет текст, "нарушением" считается и обещание/заявление "я оформил возврат". Вызовы функций (как в τ-bench) можно добавить позже.
